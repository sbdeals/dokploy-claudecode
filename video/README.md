# Switchyard hardening: screen recordings

Eight h264 mp4 clips (1280x800, 30 fps), four flows recorded twice: once
against the untouched `main` tip (`before/`, commit 1fc46d5) and once against
the fix branch `harden/authz-docs-polish` (`after/`, commit 460679d). Same file
names on both sides; play them side by side.

Every clip has a caption strip along the bottom that names the step, the
identity or cookie in use, what `main` vs. the fix should show, and (for pages)
the live `document.title` and URL. A red **BEFORE** or green **AFTER** tag on
the strip says which build is on screen.

Both builds talk to a fake Dokploy API (`../demo/fake-dokploy.mjs`) on a
machine with no Docker, so live metrics/logs answer "unavailable" in both;
the HTTP status codes and page states are the evidence.

## How they were recorded

Script: [`../demo/record.mjs`](../demo/record.mjs) (Playwright `recordVideo`
on a 1280x800 context, deviceScaleFactor 1, `pressSequentially` with a 70 ms
per-key delay, 1.5–5 s pauses after every state change). The API flows open a
local dark-terminal transcript page (`file://…/transcript.html`, generated by
the script); each request is performed from Node with an explicit `Cookie`
header and then appended to the on-page table, with a 2 s pause per row so it
visibly grows. Session cookies come from `../demo/mint-cookie.mjs`, which
mirrors `dashboard/src/lib/session.ts`. Conversion: [`../demo/convert.mjs`](../demo/convert.mjs).

Browser: the Chromium Playwright had already cached
(`~/Library/Caches/ms-playwright/chromium-1228`); Playwright's bundled ffmpeg
(`ffmpeg-1011`) wrote the raw `.webm`. `/opt/homebrew/bin/ffmpeg` 8.1.2 produced the mp4s.

```bash
ART=/Users/eliyumn/Desktop/switchyard-harden-artifacts
TMP=/Users/eliyumn/.claude/jobs/b0cd646f/tmp/demo       # any scratch dir; needs `npm i playwright-core` in $TMP/pw (PW_DIR)

# fake Dokploy
PORT=3971 FAKE_DOKPLOY_LOG=$TMP/fake-dokploy.log node $ART/demo/fake-dokploy.mjs &

# BEFORE: `git archive` of main 1fc46d5 -> $TMP/before/dashboard, `cp -Rc` node_modules in, `npx next build`
# AFTER:  `git archive` of 460679d      -> $TMP/after-src/dashboard, same steps
ENV="DOKPLOY_URL=http://127.0.0.1:3971 DOKPLOY_EMAIL=admin@demo.test DOKPLOY_PASSWORD=password-admin SWITCHYARD_SESSION_SECRET=demo-secret-do-not-use SWITCHYARD_COLLECT_INTERVAL_MS=5000"
(cd $TMP/before/dashboard    && env $ENV npx next start -p 3972 &)
(cd $TMP/after-src/dashboard && env $ENV npx next start -p 3973 &)

cd $ART/demo
node record.mjs all http://127.0.0.1:3972 $TMP/video-raw/before before
node record.mjs all http://127.0.0.1:3973 $TMP/video-raw/after  after
node convert.mjs $TMP/video-raw $ART/video      # webm -> mp4 (libx264, yuv420p, crf 22, 30 fps, faststart) + size/duration table
```

`record.mjs <clip>` re-records a single clip (`login`, `forged`, `crossuser`,
`expired`). The 30 s cache-TTL wait from the screenshot pass is skipped in the
video; the TTL edge is in `../before/07-cross-user-allowlist.md`.

Not recorded: the collector identity finding (it is a 60 s idle-window log
count, see `../before/10-collector.png` vs `../after/10-collector.png`), the
Secure-cookie flag (a cookie-jar attribute, see `11-secure-cookie.md`), and
the http-metrics fail-open case (needs the stub stopped mid-clip; see
`09-http-metrics-fail-open.png` on both sides).
